# AISBench 客户端接口兼容性核查

AISBench 是**评测客户端，不是 OpenAI 兼容服务端**。核查的是选定配置如何构造/发送请求、消费响应，以及是否满足该评测链路的契约；不是替后端出具兼容认证。实现和测试是实际行为证据，不是协议正确性的来源；不得凭记忆判断默认值。

## 1. 先限定责任和支持面

在查字段前记录：

- AISBench commit、问题/改动、配置名及实际 `type`，是否插件或独立任务；后端产品/版本、模型能力、代理路径（未知就写未知）。
- 协议面、HTTP 方法与**最终 URL 路径**、流式开关、输入类型、输出类、评测模式；例如 `VLLMCustomAPIChat` 的 `POST /v1/chat/completions`，不能只写“OpenAI API”。
- 字段/事件/错误的最小问题，以及本次承诺消费的内容：文本、tool calls、多模态、usage、logprobs 等。
- 分清 AISBench 配置值、发出的 wire JSON、后端行为、AISBench 解析/后处理四层；用户参数可配置不代表后端支持，也不代表评测器使用了响应字段。

仅检查仓库中**已有适配或本次改动触及的路径**。OpenAI Chat/Completions、MindIE 原生、TGI、Triton、VITA 的契约不混用。同一后端也可能走不同协议。不要把未覆盖的 Responses、Embeddings、Audio 或 Anthropic 当成必须补齐的缺陷。新增协议需求应单独界定，不在本技能中自动扩展实现。

## 2. 沿真实调用链取证

按需打开 [实现、测试与文档导航](<references/evidence-map.md>)，先核对当前 checkout，导航基线不等于永远不变的事实。

1. 从配置到模型注册/构建，确认实际使用类与覆写方法。跟踪 prompt/template → message/body → URL/header → 发送 → SSE/JSON → Output → 评测消费端。必要时追到 inferencer 与后处理，不仅看字段声明。
2. 为每个字段列出：输入值 → 合并/覆盖/移除 → 最终 JSON → 响应读取位置 → 保存/使用位置。区分“透传”“强制覆盖”“静默忽略”“显式拒绝”“只存档不参与评测”。
3. 记录 `file:line` 及最小脱敏样例。不要从文档“原样透传”的概括跳过实现：本仓有强制 `model`/长度、`stream_options` 合并顺序和内部开关移除等例外。
4. **SDK 与原始 HTTP 分开核查**：当前主适配是 `aiohttp` POST，模型自动发现是 `requests` GET。存在 `openai` 依赖不代表主链路经过 SDK。只有找到实际 SDK 调用方才检查其版本、`NOT_GIVEN`/`None`、`extra_body`、序列化、重试、超时和异常；不得将 SDK 参数封装原样当作 HTTP JSON。

## 3. 固定对照来源，明确证据层级

用 [已确认的外部入口](<references/evidence-map.md#外部来源与版本>) 按需查证，**不照抄参考技能里的浮动或失效 URL**。

- **官方协议/OpenAPI 与语义文档**：回答 wire 字段、可空性、缺省、事件与错误契约。固定 commit/tag；无版本页面记录访问日期、最终 URL、相关原文与快照/摘要，不假装它不可变。
- **官方 SDK 类型/实现**：标注包名和精确版本（从已安装包元数据或固定 tag 读取），作为类型/客户端行为证据，不把 `Optional` 或 Python 默认值当成服务端默认值。仓库的未锁定依赖不能给出实际安装版本。
- **目标后端文档/实现**：按实际发布版查支持子集、模型限制和扩展；vLLM 文档不是 OpenAI 官方规范，MindIE/TGI/Triton 原生接口也不受 OpenAI 同名字段自动约束。
- **AISBench 文档、代码、离线测试、用户提供的脱敏流量**：证明客户端行为与声明，不证明官方规范或真实服务行为。

每条关键判断保存来源类型、版本/commit、URL/路径、访问日期、章节/原文和适用协议。来源冲突应分别列出，按问题归属判断，不强行选一个“最新”替代目标版本。HTTP 403/404、截断、动态页面或离线不可访问是**取证失败**，不是字段不存在；降级到固定 SDK/后端资料时保留结论限制，无法判定则标未知。

## 4. 比较矩阵（只展开与问题有关的行）

| 轴 | 必查事项 |
| --- | --- |
| 请求字段 | 名称、类型、枚举、范围、嵌套位置；未提供 vs `null` vs 空串/空数组/`0`/`false`；客户端默认、后端默认分别是什么；未知字段、`generation_kwargs` 冲突、内部参数是否泄漏；`max_tokens` 与其他长度字段不能直接视为同义 |
| 消息/能力 | role 映射、模板转换后是否保留额外字段；文本/内容块、tool call id/arguments、拒答及多 choices 的消费方式；明确支持子集，不要求保存全部上游字段，但不得把丢失评测所需内容称为兼容 |
| 发送 | 完整 URL/路径前缀、模型发现、header/auth、编码；配置的 `stream` 与最终 body 是否一致；SDK `extra_body` 展开与直接 JSON 透传的差别 |
| SSE | TCP 分片不是事件/token；LF/CRLF、跨包 UTF-8、空行、注释、`id:`/`event:`、多行 `data:`、空 delta/role-only、tool-only、结束原因；按选定协议检查 `[DONE]`、EOF、截断、流内错误，不能把其他协议终止方式套进来 |
| usage | 缺省/`null`/空对象、usage-only 且 `choices=[]`、总量 vs 增量、零值、末尾 usage 未到达；区分服务端计数、初始化零值、本地 tokenizer 和估算值，不把缺失当可靠零值 |
| 错误/重试 | 非 200 的 status、body `type`/`code`/message、header/request-id 是否保留；HTTP 4xx/429/5xx 与 DNS/连接/TLS/超时/取消不同；200 非 JSON、流中断/错误对象、空成功、重试次数与部分内容/usage/时间点是否重置，不能假定失败一定重试 |
| 计时边界 | POST 前、首事件、首内容/token、usage-only、`[DONE]`、读完与解析后各在何时打点；重试/连接复用/缓冲影响。核对 Output、落盘、calculator 的消费，不因协议可解析就认定 TTFT/ITL/TPOT、token 数或性能结论正确 |

## 5. 最小离线验证优先

优先使用现有 mock/fixture，参考 [快速开始](<README.md#离线验证入口>)。以合成输入抓取最终 body/header，并将合成 JSON/SSE 喂入**实际选定方法**；不要另写一个“正确解析器”替代被测代码。最小用例按需包含：

- 同一字段缺省、显式 `null`、合法边界及非法类型；冲突合并前后 JSON；模板入口与直接 body 入口的差异。
- 非流式、文本 delta、role-only、tool-only、usage-only、`[DONE]`、缺失终止、半包/多包/多行 data、坏 JSON/流中错误。
- HTTP 错误与网络异常分开注入，断言 success/error、已累积内容、usage、尝试次数和时间点；计时用可控时钟，不用真实负载证明语义。

只运行相关小范围测试；先读测试以确认 mock 覆盖和协程确实被 await。通过数、skip、警告、收集失败/缺依赖和未测分支均需记录。**测试通过仅说明所选用例，不代表整套 API 已兼容。** 不复刻覆盖率/CI 门禁，不为了本技能额外造脚本。

默认不访问真实推理端点，不发送任何密钥/真实数据，不部署服务、下载模型或跑大规模测评；注意模型构造时空 `model` 可能触发发现请求，应显式给合成模型名或 mock。外部文档取证不等于真实端点调用授权。只有用户明确授权具体目标、请求/预算上限与凭据使用方式后，才另行计划最小在线验证；证据须脱敏，不能将 header/body 的敏感值写入报告。

## 6. 分类后报告，保留未知

先声明客户端责任/支持面，再逐条分类，不能把所有差异叫 bug：

- **所查行为一致**：固定来源与所选客户端用例一致；注明静态/离线/在线证据级别，不外推整体兼容。
- **后端扩展**：非官方字段/行为有目标后端依据；记录版本和透传方式，不当成官方字段，也不凭“扩展”豁免同名字段语义冲突。
- **明确支持子集/不适用**：仓库未声明消费的能力或不走该路径；说明限制。配置/文档承诺支持却静默丢弃是另一类问题。
- **客户端不兼容/实现缺陷**：在已声明/本次选定支持面内，请求构造、解析或消费违约；区分显式拒绝与接受后忽略，给出最小修复方向及回归用例，不自动改业务代码。
- **后端差异或文档漂移**：来源明确指向后端限制，或本仓文档与实现冲突；标明责任层，勿误归因 AISBench。
- **未知/未验证**：缺版本、来源抓取失败、缺环境、未获在线授权或证据不足；列下一步所需证据。网络失败本身不证明协议不兼容。

报告至少包含：范围/版本、字段或事件、预期及来源原文、实际及 `file:line`、字段流向、分类/责任层、对解析/计时/评测的独立影响、最小复现与已跑测试、修复建议、未知与限制。API 协议一致、性能计时正确、评测正确须分别给证据，绝不互相替代。
