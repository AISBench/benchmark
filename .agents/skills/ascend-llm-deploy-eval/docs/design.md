# 设计说明

## 配置与职责

Agent 将自然语言需求和参考脚本整理为 job_spec v3，并通过只读现场探测完成语义审阅。job_spec 保存部署、负载和执行顺序；bindings 保存主机、权重、网络、端口、挂载及数据源。程序检查结构、依赖和绑定，Agent 判断架构、并行策略、上下文及参考参数是否完整。确认后的配置不在执行中静默调整。

`deployments` 定义模型和代理拓扑，`cases` 定义负载，`sub_tasks` 引用部署和负载。默认串行；显式 `stages` 可表达阶段内独立分支并行、分支内串行。`phase_id` 本身不引入并行。阶段间必须完成资源释放和产物汇集。

## 执行架构

唯一生命周期入口为 `scripts/run.py`。`scripts` 模式只生成可审阅脚本；`FULL` 模式在 Linux 主节点运行一个协调器，通过 SSH 管理其他节点。两种模式使用相同的确定脚本。

执行顺序为配置校验、分发、资源占用检查、创建容器、全部容器依赖检查、启动模型与代理、健康检查、冒烟、AISBench 性能测试、结果核验、释放与汇集。依赖检查不执行 bootstrap。代理默认等待其模型端点健康后启动。

远程运行时由 `publish_runtime.py` 发布必要模块、Schema 和指定输入，记录文件摘要与任务身份。运行时和任务目录分开，已有任务目录拒绝覆盖，不在运行中更新冻结代码。

## 性能测试与数据

AISBench 负责请求发送和性能统计。普通测试默认正式请求数为并发×4，稳态测试为并发×10；显式总数优先，预热另计。稳态选择 `stable_stage`，不自动开启按时长循环压测。选中统计器不代表实际稳态区间一定有效。

前缀测试使用 AISBench 原生 SyntheticDataset，按输入目标和比例配置 RequestSize、PrefixLen；真实文件测试使用外部 JSONL/CSV。目标前缀、实际公共前缀和缓存命中率分别表达。原生合成数据重新分词后的长度偏差仅记录，不作为精确长度失败条件；请求失败、数量不符、输出超上限和必要结果缺失仍失败。

## 状态、资源与产物

协调器唯一写入 status.json。任务目录保存输入、生成脚本、服务日志、AISBench 原始结果和最小运行信息。同部署可复用服务，不混合不同 case 或重试的结果。

仅释放本任务身份匹配的容器和资源；默认 case 后保留服务，任务结束停止容器。释放无法核验时停止推进，不处置其他任务资源。任务目录、共享镜像和权重不随资源释放删除。

重试有次数上限，仅针对允许的传输及非测试阶段连接故障。中断采用协作式取消，正在执行的远端调用可能持续到超时后才收尾；发送中断不等于资源已释放。任务锁冲突或执行状态不明时保留现场，不删除锁并重放任务。

## 接口与范围

具体命令、目录和配置见[统一 CLI](compact-cli.md)，参数审阅见[审阅规则](../references/job-spec-review.md)，数据语义见[原生前缀数据](generated-data.md)。当前支持性能测试，不支持精度执行、复杂自动恢复或 stop_service 清理策略。多 P/D 的代理及连接兼容性需要现场核验。
