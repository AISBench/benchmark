# 信息收集与需求交接

复用已有事实，只问实际缺项；可探测的工具路径、版本、网络和端口由Agent核验。首次回复聚焦目标与访问条件，不附加默认执行规则、工具检查职责或通用能力边界说明。具体能力缺口出现时及时说明。

## 缺项模板

用户可直接用自然语言提供，不要求逐项填表或填写JSON：

```text
服务器地址/SSH别名、工作目录：
特殊权限或资源限制（如有）：
模型及权重路径（tokenizer路径不同则补充）：
镜像名称/tag或ID：
部署脚本或命令（本地路径、远程路径或粘贴内容）：
数据：AISBench 原生合成，或真实数据集路径、格式及字段：
最大输出长度（1K=1024 tokens）；可选输入长度校验：
并发数：
请求数、预热次数及日志目录（如需覆盖默认值）：
特殊测试要求（如有）：
```

替用户生成任务提示词时只保留任务事实和特殊要求；不要求重复授权既定预检、清理和监控行为。

## 整理与交接

按“服务器 → 部署 → 负载组合”提取对应关系，不把用户未明确的列表展开成笛卡尔积。case是内部管理单元，不限制首次对话范围。多模型、部署或case按[多任务规划](multi-task-planning.md)处理。

统一token单位与比例，分配稳定标识；按[配置与绑定](job-spec-review.md)形成deployments、cases、sub_tasks。源脚本经审阅后提取参数，现场事实放bindings/resolved。展示给用户的摘要聚焦服务器分配、部署、负载和实际阻塞，不要求其理解内部Schema。

## 无需首次询问的字段

- 请求数、轮数及预热参数按[配置默认值](job-spec-review.md)补齐；用户覆盖优先。
- 缓存默认不主动清理；预热使用 AISBench 的 num_warmups，特殊要求按[生命周期](service-lifecycle.md)处理。
- AISBench从镜像中动态发现；路径或版本有歧义时再报告缺项。原生合成数据由 AISBench 生成；真实数据使用用户指定外部路径，不随 Skill 上传。

## 现场核验

核验模型/镜像、必要权重和tokenizer文件、命令配置、设备权限、挂载、网络端口及工具结果解析能力。整机独占需求不授权终止其他任务；已有本任务服务应核验身份，不能当成外部占用。历史PID、空闲结论或旧冒烟不证明当前实例有效。预检通过后按冻结计划执行；运行与释放策略统一见生命周期。

## 标准 CLI 现场输入

确认容器内已安装可运行的 AISBench。前缀测试绑定 aisbench_synthetic，详见[原生前缀数据](../docs/generated-data.md)；真实数据绑定 JSONL/CSV 路径及字段，由 case.dataset_id 引用。PD 代理从参考目录提取并明确绑定。默认保存原生日志，配置与结果说明见[CLI 适配](../docs/native-cli.md)。
