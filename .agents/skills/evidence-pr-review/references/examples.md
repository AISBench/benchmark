# 检视示例

## AISBench Prefix Cache

本例演示如何把通用检视流程应用于具有多 Lane 轨迹与缓存状态的算法优化。以下内容用于设计检视与验证，实际执行时核对目标版本的实现、契约和测试，并记录真实结果。

| 通用步骤 | 示例应用 |
| --- | --- |
| 提取工程约束 | 核对 Cold/Warmup、Group、Rank、Lane 与全局累计指标的定义，明确容差与验收范围 |
| 追踪影响路径 | 从生成请求的入口追踪 Lane 分配、缓存状态、命中率计算与诊断状态的调用方 |
| 设计最小反例 | 构造两个 Lane 交错执行的少量请求，分别计算 Lane 内轨迹和全局累计命中率 |
| 执行验证 | 复用目标版本的轨迹检查测试，记录输入、局部与全局结果、诊断输出和断言 |
| 判定结论 | 根据验收要求确认下降现象是否违反约束，并将运行证据、代码推导与待确认项标明 |

假设测试显示全局累计命中率短期下降，先确认验收口径。若契约仅要求 Lane 内轨迹满足约束，且相应验证通过，可记录为设计允许行为。若契约要求全局单调，需继续核对该输入是否受支持，以及实际执行是否违反约束。契约缺失时，将“全局单调是否属于验收要求”列为待确认项。

同样可以按具体改动选择其他候选问题。

- 缓存隔离。用两个不同 Tokenizer 对相同输入交替调用，检查缓存键与结果是否保持隔离。
- 副作用。调用 `inspect`，结合契约检查 Tokenizer 加载、文件写入等可观察行为。
- 回退路径。构造主策略无法满足条件的输入，验证 `BEST_EFFORT` 的触发条件、返回状态与调用方处理。
- 大规模路径。结合代码与规模测试确认慢路径的可达条件，并在同条件下测量性能和正确性。

将本例迁移到其他项目时，使用目标项目的状态划分、统计口径、隔离维度和降级契约设计反例。
