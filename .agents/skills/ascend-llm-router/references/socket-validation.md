# Model-free Linux socket acceptance

Requires CLI 0.1.0a4, SSH, Linux Python >=3.11 with jsonschema, and permission to create task processes and files. No model, Docker or NPU is used. Stage results are SIMULATED and performance is UNVERIFIED. This is not production validation.

Create a new task_ref and a new absolute task root below the authorized work root. Create control.json with tasks[TASK] containing host, root, allowed_root and absolute python. Generate and save a 64-character hex nonce once. Write start.json containing exactly task_ref and nonce.

Run `deploy-eval-v2 --config control.json socket-start --request start.json`. This packages the installed runtime, publishes it with digest verification, starts an explicitly fake detached Python runtime, and attests its live socket identity. Save runtime_sha256, bundle_sha256 and runtime evidence. No production frozen input is used; bundle_sha256 identifies the immutable simulated-input marker. Do not reuse this task for production. A lost response requires the SAME task root and nonce; do not start a new identity to bypass uncertainty.

The Agent now calls the installed deploy skill and normal CLI deploy, with task_ref, a saved request_id, expected_version from get-status, plan_ref equal to the returned bundle_sha256, and wait_ms=1000. Save operation_id and next_cursor. Use wait-event if RUNNING. Once deployment.ready arrives, check get-status, load the eval skill and call eval with service_id=fake-service and case_id=socket-case. Once evaluation.completed arrives, check status, load release and call release with service_id=fake-service. The usual request fields apply. Fake evidence refs are placeholders; record SIMULATED rather than claiming real health or benchmark evidence.

Replay an identical deploy request and verify the same operation_id. Query wait-event after the final delivered next_cursor with wait_ms=10 and verify WAIT_TIMEOUT. Each CLI invocation closes its SSH connection; a subsequent get-status must reconnect to the same runtime. Record request/response files, per-command exit code and response byte count. Stage release simulates resource release; it leaves the observer runtime available. After final evidence collection, run `deploy-eval-v2 --config control.json stop-runtime --request start.json` using the original task_ref and nonce. Verify runtime_stopped=true. Preserve task files. Do not guess PIDs or use system service operations.

Unknown-outcome, cancellation and idle-release injection require separate documented scenarios; the simple fake run does not prove these production behaviors.
