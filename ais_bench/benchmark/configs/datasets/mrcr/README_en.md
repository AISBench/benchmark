# MRCR (Multi-Round Co-reference Resolution)
[中文](README.md) | English

## Dataset Introduction

MRCR (Multi-Round Co-reference Resolution) is a long-context multiple needle-in-a-haystack benchmark released by OpenAI alongside GPT-4.1 (MIT license), inspired by the MRCR eval first introduced by the Gemini team (arXiv:2409.12640).

Task setup: the model reads a long (up to ~1M token) multi-turn synthetic conversation in which the same writing request (e.g. "write a poem about tapirs") appears 2/4/8 times among same-distribution distractor requests (all assistant responses are generated by gpt4o, so the needles blend in with the haystack). The model is finally prompted to return the Nth instance of one of those asks, prepending a given random string:

```
User: Prepend aYooSG8CQg to the 2nd (1 indexed) poem about tapirs.
      Do not include any other text in your response.
Assistant: aYooSG8CQg (the 2nd poem about tapirs)
```

The challenge: needles and distractors are drawn from the same distribution and are indistinguishable in style; the model must also distinguish the order among the identical asks. More needles and longer contexts make the task harder.

The data is split into `2needle` / `4needle` / `8needle` subsets by needle count; each subset is bucketed into 8 bins by the `o200k_base` token count of prompt+answer, with 100 samples per bin (~800 samples per subset, ~2400 in total).

The official evaluation protocol is purely rule-based (no LLM judge): the response must start with `random_string_to_prepend`, otherwise it scores 0; after stripping the prefix from both sides, `SequenceMatcher(None, response, answer).ratio()` is computed; the final score is the mean ratio over all samples.

## Dataset Deployment

- Obtain the dataset from the Hugging Face link 🔗 [https://huggingface.co/datasets/openai/mrcr](https://huggingface.co/datasets/openai/mrcr).
- The MRCR dataset is in Parquet format, organized into one directory per needle subset. It is recommended to deploy it under `{tool_root_path}/ais_bench/datasets/MRCR/`:

```bash
huggingface-cli download openai/mrcr --repo-type dataset --local-dir {tool_root_path}/ais_bench/datasets/MRCR
```

- Execute `ls` in the `{tool_root_path}/ais_bench/datasets/MRCR/` directory to check the directory structure. If the directory structure is as shown below, the dataset has been deployed successfully (shard count may vary with the release):

```
{tool_root_path}/ais_bench/datasets/MRCR/
├── 2needle/
│   ├── 2needle_0.parquet
│   └── 2needle_1.parquet
├── 4needle/
│   ├── 4needle_0.parquet
│   └── ...
└── 8needle/
    ├── 8needle_0.parquet
    └── ...
```

## Slicing Configuration (subset / length_bin)

The dataset configuration supports two slicing parameters (see `datasets/mrcr.py` and `mrcr_1m_gen.py`):

- `subset`: needle-count sub-directory name, one of `2needle` / `4needle` / `8needle`.
- `length_bin`: filter by the official bin boundaries (`o200k_base` token count of prompt+answer), one of `8k` / `16k` / `32k` / `64k` / `128k` / `256k` / `512k` / `1m`; `None` disables filtering (full set, fast smoke-test path).

| bin  | token range       | bin   | token range           |
| ---- | ----------------- | ----- | --------------------- |
| 8k   | [4096, 8192]      | 128k  | (65536, 131072]       |
| 16k  | (8192, 16384]     | 256k  | (131072, 262144]      |
| 32k  | (16384, 32768]    | 512k  | (262144, 524288]      |
| 64k  | (32768, 65536]    | 1m    | (524288, 1048576]     |

The default task `mrcr_1m_gen` uses `subset='8needle'` and `length_bin=None` (all 8 bins, ~800 samples), matching the public methodology of technical reports (e.g. DeepSeek-V4's "MRCR 1M"): 8needle averaged over all bins from 8K to 1M. All bins have the same number of samples (100), so the mean over all samples equals the per-bin macro average.

## Inference Parameter Alignment Notes

| Parameter   | Recommended | Description                                                                                                                                  |
| ----------- | ----------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| temperature | 1.0         | The official runner passes no sampling parameter (OpenAI API default 1.0); a local vLLM service may ship generation_config with temperature=0.0, so set it explicitly in the model's generation_kwargs to avoid silent deviation |
| max_out_len | >= 8192     | The official runner does not limit output; needle answers are ~1K tokens, but a thinking model's reasoning tokens count against the output budget — an insufficient budget truncates the final answer and the prefix gate scores 0 |

- Thinking models: when reasoning content is returned separately from the final answer, the evaluator automatically grades the reasoning-free `content` field (the `prediction` field concatenates reasoning content and would always fail the prefix gate).
- `--num-prompts` truncates sequentially and may only cover the first bin; partial runs are not representative. Run the full set (~800 samples for 8needle, up to 1M tokens per sample) when comparing against public reports.

## Usage Example

```bash
# Inference (temperature=1.0 to align with the official protocol, max_out_len >= 8192 recommended)
ais_bench -m infer --models vllm_api_general_chat --datasets mrcr_1m_gen
# Evaluation (pure rule-based scoring, no judge model required)
ais_bench -m eval --models vllm_api_general_chat --datasets mrcr_1m_gen
```
