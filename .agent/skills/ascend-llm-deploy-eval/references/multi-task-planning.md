# 多模型、多部署与多case规划

仅在出现多个模型、部署或case时读取。按用户指定关系整理模型、部署和负载矩阵；仅对会改变测试范围的歧义提问。“全部配置”以参考目录实际识别出的部署形式为依据，不臆造组合。

## 资源分组

- 独立服务器可分成并行任务；同一服务器上的多个部署优先纳入一个串行job_spec，以便复用兼容容器。不规划同机分卡并行。
- 每个任务使用唯一job_id、任务目录及资源归属；不要把相同case自动复制到每台服务器，除非用户要求重复对比。
- 仓库外规划记录保存原始需求、case对应关系、主机分配、依赖及状态。不要向job_spec添加未实现的调度字段，phase_id不是并行屏障。
- 双机任务需要复用前置单机资源时，显式设置依赖；启动条件和释放核验统一按[整组执行](group-execution.md)，不能只凭进程退出放行。

全部子任务完成预检后提交整组，由远端协调器自动衔接。整组只建立一个应用监控，各任务保留独立执行记录；具体见[任务监控](task-monitoring.md)。

面向用户展示部署、负载、服务器分组和阻塞项；保留每个case及清理结果，明确区分已规划与已现场验证。拆分不改变负载、部署参数或测试次数。
